# 160개 성능 측정 조건

최종 성능 행렬의 160개 조건은 다음 조합으로 구성한다.

```text
5개 데이터셋
× 2개 프로그램
× 2개 압축 포맷
× 2개 작업
× 4개 요청 스레드
= 160개 조건
```

## 조합 항목

### 데이터셋 5개

1. `large-text`: 반복 텍스트 중심 대용량 파일
2. `incompressible`: 압축이 거의 되지 않는 의사 난수 데이터
3. `small-files`: 작은 파일 1,500개
4. `mixed-project`: 소스·문서·리소스가 섞인 프로젝트형 데이터
5. `large-file`: 단일 대용량 파일

### 프로그램 2개

1. Bandizip
2. yzip

### 포맷 2개

1. ZIP
2. 7z

### 작업 2개

1. 압축 생성(`compress`)
2. 압축 해제(`extract`)

### 요청 스레드 4개

1. 1 thread
2. 4 threads
3. 8 threads
4. 16 threads

스레드 값은 프로그램에 전달한 요청값이다. 실제 내부 worker 수를 측정한 값으로 표현하지 않는다.

## 실행 횟수

각 조건은 다음 순서로 실행한다.

- 준비 실행(warm-up): 1회
- 공식 측정: 7회

따라서 160개 조건의 프로세스 실행은 총 1,280회다.

```text
160개 조건 × (warm-up 1회 + 공식 측정 7회) = 1,280회
```

아카이브 준비, 교차 제품 해제, SHA-256 파일 트리 검증은 위 숫자와 별도로 수행한다.

## 측정·검증 항목

각 조건에서 다음 값을 기록하거나 검증한다.

- 전체 실행 시간의 median과 p95
- CPU 시간
- peak RSS
- 생성 아카이브 크기
- 요청 스레드 수와 실제 실행 명령
- 반대 제품으로 교차 해제한 결과의 SHA-256 파일 트리 일치 여부
- 현재 yzip과 기존 기준 결과의 7z 8-thread 압축 회귀 여부

숫자가 같은 압축 레벨 5를 양쪽에 전달하지만, 제품별 내부 코덱 매개변수가 완전히 같다는 뜻은 아니다. 결과는 동일 원본에서 각 제품의 명목상 레벨 5를 사용한 CLI 종단 간 비교로 해석한다.
