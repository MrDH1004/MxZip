# MxZip v1.0.22 작업 내역 (2026-11-01)

브랜치: `feat/native-performance` → `main` 병합 완료. 두 브랜치 모두 `e280a47`.

## 1. 종료 시 크래시 수정 (`8a204ce`)
- 원인: `ExitProcess` → DLL_PROCESS_DETACH → shiboken6 `BindingManager::~BindingManager` → `Object::destroy` → `releaseWrapper`에서 널 포인터 접근.
- 수정: `appcore.hard_exit()`가 stdio flush 후 `TerminateProcess`로 종료. `mxzip_main.py`, `mxzip_gui.finish`/`__main__`는 예외를 잡아 기록한 뒤 `hard_exit`로 나간다.
- 검증: 수정 전 80회 중 5회 크래시 → 수정 후 단독 120회, 동시 60라운드 모두 0회. `exe_verbs_smoke` 57/57 ×3.
- 테스트: `test_hard_exit.py` (FLS 콜백 프로브로 정상 종료 경로를 타지 않는지 확인).

## 2. 7z 헤더 직접 읽기
- `sevenzip_header.py` 신규: 7zFormat 명세대로 헤더를 읽어 py7zr import(~0.13 s)를 피한다. 지원하지 않는 코더는 `Unsupported` → py7zr로 넘어간다.
- 압축 시 헤더를 LZMA2 인코딩 헤더(kEncodedHeader)로 쓰고, 압축이 안 되는 데이터는 LZMA2 비압축 청크로 저장.
- 테스트: `test_sevenzip_header.py`.

## 3. 제품명 MxZip 변경 / 아이콘 (`8598034`, `9c1ff21`)
- 화면 문자열, 설치 프로그램(AppName MxZip, 게시자 YMX), 셸 메뉴, 버전 정보, README 변경.
- 업데이트 호환을 위해 내부 이름(`MxZip.exe`, 설치 폴더, 레지스트리 키)은 유지.
- 아이콘: YMX 로고 색 + 지퍼, 흰 타일(시안 E). `make_icon.py`, 시안 생성용 `make_icon_concepts.py`.

## 4. 성능 개선 (`2dc42ae`, `d2aa14f`)
- 시작 비용: 지연 import(`_LazyModule`), dataclass 대신 일반 클래스, argparse 없는 빠른 인자 파서.
- 스레드 풀: threading 기반 경량 풀, 남은 작업이 5 ms 미만이면 인라인 실행.
- 압축 해제: 폴더별 realpath 캐시(`TargetResolver`), 새 파일은 `"xb"`로 바로 쓰기, 열린 핸들에 `SetFileTime`, 16 MB 이상 ZIP 항목은 write-behind.
- 시도 후 되돌림: 256 KB 7z 블록(압축 파일 37% 커짐).
- 타사 압축 프로그램 대비(교대 측정 7회, 중앙값, 기하평균):

| | 개선 전 | 개선 후 |
|---|---|---|
| 압축 | 63% | 110% |
| 압축 해제 | 36% | 75% |
| 전체 | 48% | 91% |

- 한계: 작은 작업의 압축 해제는 Python 시작 비용(~0.06 s) 때문에 30~50% 수준.

# MxZip 1.0.5 ~ 1.0.7 작업 내역 (2026-11-08)

`main`(= `feat/winforms-viewer`) `91d91a3`. 릴리스: [1.0.5](https://github.com/MrDH1004/MxZip/releases/tag/v1.0.5), [1.0.6](https://github.com/MrDH1004/MxZip/releases/tag/v1.0.6), [1.0.7](https://github.com/MrDH1004/MxZip/releases/tag/v1.0.7) (모두 서명 없음).

## 1. 우클릭·연결 프로그램 수정 (`08108e8`)
- `.exe` 우클릭: 압축 풀기 대신 압축하기만 나온다. `formats.SHELL_ARCHIVE_EXTS`에서 `.exe` 제외.
- "연결 프로그램(추천 앱)"에 MxZip 표시: `assoc.offer()`를 `--register-shell`에서 호출. 사용자가 이미 기본 앱을 고른 확장자만 `OpenWithProgids`(추천 앱), 나머지는 `Applications\<exe>\SupportedTypes`(기타 옵션). 고른 앱이 없는 확장자에 `OpenWithProgids`를 넣으면 Windows가 기존 연결을 버리고 선택 창을 띄우는 것을 테스트로 확인했기 때문.
- `assoc.enabled()`는 "확장자 기본값이 MxZip ProgID"일 때만 참(목록에만 오른 상태는 연결 아님).

## 2. 새 압축 파일 창 MxZipViewer (`08108e8`, C# WinForms, `winforms/`)
- 이유: Qt 창이 뜨는 데 0.9초. 원인은 Python+Qt 로딩과, Qt가 첫 창을 띄울 때 Direct3D로 그래픽카드를 조회하는 비용(`qwindows.dll`의 `GpuDescription::detect`, REA로 확인, 이 PC에서 0.1~0.25초).
- 구조: 창만 C#(.NET 9 framework-dependent, ReadyToRun, `RollForward=Major`). 형식 처리는 기존 Python 엔진이 Qt 없이 처리(`viewer_engine.py`): `--list-json`, `--extract-to`, `--test-json`, `--delete-json`, `--add-json`, `--update-check`. 결과는 JSON 파일, 진행률·취소는 `RESULT.progress`/`.cancel` 파일, 암호는 stdin.
- 그 밖의 인자(메뉴·설치·업데이트용 `--` 명령)는 그대로 `MxZip.exe`에 넘긴다.
- 파일 연결은 .NET 9 이상 Desktop 런타임이 있을 때만 뷰어를 가리킨다(`assoc.viewer_for`). 없으면 예전처럼 Qt 창.
- 화면(ZipMania 구성 참고, 아이콘은 MxZip 색으로 직접 그림): 열기·풀기·새로 압축·파일 추가·파일 삭제·오류 검사·정보·전체 보기·다크 모드·환경설정, 기본 앱 안내 띠, 파일 끌어 놓기 빈 화면, 경로 표시줄, 진행률·취소.
- 속도(숨겨진 데스크톱, 0.9MB zip): 창 0.18~0.24초, 목록 0.30~0.43초. 타사 압축 프로그램 0.30/0.33초, 예전 Qt 창 0.66~0.92초.

## 3. 우클릭 압축 풀기 4개 메뉴 (`08108e8`)
- 여기에 풀기(Z) / 알아서 풀기(Z) / `<이름>\ 에 풀기(E)` / MxZip으로 압축 풀기(B)...
- "여기에 풀기"는 이제 그 자리에 바로 푼다(예전엔 알아서 풀기처럼 동작). "알아서 풀기"는 최상위 항목이 여럿일 때만 폴더를 만든다.
- `MenuMask` 비트 8(알아서)·16(창)을 추가하고 0x80으로 새 형식을 표시한다. 예전 값(7)이면 새 두 항목도 보인다. 환경설정 > 탐색기에서 켜고 끌 수 있다.

## 4. MxZip 실행 시 새 창 (`06b412b`, 1.0.6)
- 인자 없이 실행, 압축 파일 하나, 업데이트 후 재시작(`--updated`)이면 Qt를 불러오기 전에 뷰어로 넘긴다. 업데이트 직후에는 상태 표시줄에 업데이트한 버전을 표시한다.
- 예전 홈 화면이 하던 자동 업데이트 확인을 뷰어가 이어받았다(`--update-check`, 새 버전이면 "지금 업데이트" 안내 → `--update-now`).
- `MXZIP_QT_HOME=1`이면 Qt 창 유지. CI 업데이트 테스트(`MXZIP_UPDATE_TEST_MARKER`)는 영향 없음.

## 5. UI/UX 점검 반영과 다크/라이트 전환 (`4147414`, 1.0.7)
- 키보드 초점: 도구 버튼·카드에 2px 청록 테두리(대비 1.40:1 → 8.4:1, 밝은 테마 5.0:1), 목록 현재 행 테두리(예전엔 표시 없음).
- 창 최소 너비 = 도구 모음 폭(790px). 버튼이 잘리지 않는다.
- 토글(전체 보기, 다크 모드)은 CheckBox 기반: 켜지면 채워진 타일, 보조 기기에 체크 상태 전달.
- 삭제 확인은 TaskDialog: "n개 항목 삭제", 되돌릴 수 없음 안내, "삭제 / 취소"(기본 취소).
- 오류 문구에 다음 행동 안내(권한·파일 사용 중·디스크 부족·손상 의심) + 원문.
- 다크 모드 버튼은 MxZip `theme` 설정에 저장한다. 환경설정 > 테마를 바꾸면 열린 창도 1초 안에 따라가고(설정 파일 감시), "시스템 설정"이면 Windows 전환을 따른다.
- 어두운 테마 스크롤바도 어둡게 한다. 이 스타일이 그리는 세로줄은 `ThemedListView`가 빈 영역을 덮어 지운다.

## 6. 빌드·배포 (`29cb324`)
- GitHub 릴리스 다운로드가 반복해서 504(GitHub 쪽 장애, 우리 1.0.4 설치 파일까지 실패). `fetch_tools.ps1`에 재시도 3회와 7-zip.org·SourceForge 예비 주소를 추가했다(SHA-256 검사는 그대로).
- 저장소 이름 변경 전 yzip 태그(v1.0.5 등)가 남아 있어 v1.0.5 태그를 새 커밋으로 옮겼다. 그 과정에서 예전 커밋으로 시작된 빌드는 배포 전에 취소했다.
- CI(`release.yml`)에 `setup-dotnet 9.0.x`, `test_viewer_engine`, 뷰어 존재 확인을 추가했다.

- 전체 단위 테스트 통과(건너뜀 6). 셸 메뉴 네이티브 테스트(마스크 32가지 + 예전 값) 통과.

## 남은 일 / 위험
- 뷰어는 .NET Desktop 런타임이 있는 PC에서만 쓰인다. 설치 파일에 런타임을 포함할지, 프로그램에 동봉(약 116MB)할지 미정.
- .NET 9 지원 종료가 임박했다. .NET 10으로 올리려면 SDK 설치가 필요하다.
- 확인하지 못한 것: 200% 배율 화면, 화면 낭독기로 실제 읽기, 고대비 모드, 탐색기에서 끌어다 놓기, "지금 업데이트"로 실제 설치까지, 환경설정 창 테마 드롭다운을 직접 조작하는 경로(자동 조작 실패, 저장 함수 경로로만 확인).
- 뷰어는 언어 설정을 반영하지 않는다(한국어만). 열어 본 파일의 임시 폴더를 지우지 않는다.
- GitHub 릴리스 다운로드 장애가 다시 나면 배포 빌드가 실패할 수 있다(libarchive는 예비 주소 없음). CI 캐시 도입을 제안했다.
