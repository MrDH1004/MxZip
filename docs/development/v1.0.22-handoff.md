## 현재 배포 차단 문제

Explorer의 `--archive` 경로는 압축 결과를 정상 생성한 뒤 프로세스 종료 과정에서 간헐적으로 native crash가 발생한다.

- 종료 코드: `0xC0000005`
- WER 장애 모듈로 관찰된 파일:
  - `shiboken6.abi3.dll`
  - `pyside6.abi3.dll`
  - 일부 실험에서 `ucrtbase.dll`과 `0xC0000409`
- 동시 실행이 필수 조건이 아니며 단독 실행에서도 재현
- 충돌 시에도 생성된 archive와 내용은 정상
- `error.log`는 비어 있음

실패한 가설과 처리:

1. Qt 없는 `--archive` fast path
   - crash는 제거했지만 기존 progress/cancel/error UI가 사라지고 IPC 종료 경쟁을 새로 만들어 채택하지 않음
   - 커밋 `a566b5a`를 `bbca595`에서 완전히 revert함
2. 종료 시 강제 `gc.collect()` 제거
   - 단독 3회째 같은 Shiboken crash가 재현돼 폐기
3. `DeferredDelete`, GC 등 explicit Qt cleanup 전체 우회 후 즉시 종료
   - 단독 2회 중 1회 crash가 재현돼 폐기

같은 계열의 추측성 종료 패치를 더 쌓지 않는다. 다음 단계는 native crash stack을 확보한 뒤 구조를 재검토하는 것이다. 현재 권장 구조 후보는 장기 실행 Qt broker가 IPC와 progress UI를 소유하고 Explorer의 단명 프로세스는 Qt를 생성하지 않는 방식이다. 기존 기능과 IPC 경계를 명세한 뒤 별도 설계·TDD로 진행한다.

## 커밋하지 않은 로컬 생성물

`nativeaccel/verify-build/`에는 검증용 DLL과 pin manifest가 남아 있다. 소스가 아닌 생성물이므로 Git에 포함하지 않았다. 집 PC에서는 `nativeaccel/build.ps1`로 다시 생성한다.

`.omc/artifacts/native-performance-final/`의 raw benchmark JSON도 운영 artifact라 Git에 포함하지 않았다. 검산된 수치와 SHA-256 provenance는 `docs/performance/native-results.md`에 기록돼 있다.
